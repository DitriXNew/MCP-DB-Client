# MCPRagSearch — плагин Vanessa Automation

Внешняя обработка (плагин VA типа «Утилита»), которая поднимает MCP сервер на
внешней компоненте **http1c** (`libhttp1cWin.dll`) и — опционально — семантический
поиск по шагам VA на Rust-ядре (`rcore.dll`, коллекция `vanessa_steps`), а также
по произвольным файлам из настраиваемых коллекций (таблица «Коллекции файлов»).

Инструменты MCP не дублируются: плагин вызывает у MCPVA регистрацию всех
инструментов (`ВызватьРегистрациюИнструментовMCP`) через свой фасад, передаёт их
определения в компоненту (`tools_json`), а входящие `ToolCall` диспетчеризует
обратно в обработчики MCPVA. Ответ уходит конвертом
`{"id": ..., "body": "<сериализованный результат MCP>"}` (body — JSON-строка,
двойная сериализация — протокол http1c).

## Структура исходников

```
vanessa-plugin/MCPRagSearch/
├── MCPRagSearch.xml                      ← корневой дескриптор внешней обработки
└── MCPRagSearch/
    ├── filename                          ← имя целевого .epf (как у плагинов VA)
    ├── Ext/ObjectModule.bsl              ← ОписаниеПлагина / Инициализация
    └── Forms/
        ├── Форма.xml                     ← метаданные формы
        └── Форма/Ext/
            ├── Form.xml                  ← макет формы (панель управления)
            └── Form/Module.bsl           ← вся логика (клиент)
```

## Сборка .epf

Любым стандартным способом сборки из XML-выгрузки, например конфигуратором:

```
1cv8.exe DESIGNER /F <путь_к_базе> /N admin /P admin
    /LoadExternalDataProcessorOrReportFromFiles "vanessa-plugin\MCPRagSearch\MCPRagSearch.xml" "MCPRagSearch.epf"
    /DisableStartupDialogs /Out build.log
```

или `vrunner compileepf` / ibcmd — формат выгрузки тот же, что у плагинов VA
(version 2.10, как `plugins/УтвержденияBDD`).

## Установка

1. Собранный `MCPRagSearch.epf` положить в каталог `plugins/` рядом с
   `vanessa-automation.epf` (VA подхватывает плагины из этого каталога), либо
   открыть как обычную внешнюю обработку в той же сессии, где открыта VA.
2. Компонента — рекомендуемый путь, прямо с формы плагина:
   1. в группе «Настройки сервера» нажать гиперссылку
      «Скачать компоненту (последний релиз)» — браузер скачает
      `http1c-addin-full.zip` (`libhttp1cWin.dll` + `rcore.dll` + `DirectML.dll`)
      из последнего релиза GitHub; если прямая ссылка не работает — страница
      релизов: <https://github.com/DitriXNew/MCP-DB-Client/releases>;
   2. нажать кнопку «Установить из архива…», выбрать скачанный zip и каталог,
      куда распаковать — плагин распакует бандл, проверит состав
      (`libhttp1cWin.dll` обязателен; без `rcore.dll` это lite-бандл, RAG будет
      недоступен) и сам подставит каталог в поле «Каталог компоненты»;
   3. нажать «Запустить».

   Вручную: в любой каталог положить `libhttp1cWin.dll` (транспорт), а для
   режима RAG ещё `rcore.dll` и `DirectML.dll` (полный пакет http1c).
   Этот каталог указывается в поле «Каталог компоненты».

Требования: Windows x86-64, платформа 8.3.19+ (используются
`НачатьПодключениеВнешнейКомпоненты`, `Выполнить`/`Вычислить` на клиенте).

## Панель управления

| Элемент | Назначение |
|---|---|
| Режим работы (тумблер) | `MCP` — только сервер инструментов; `MCP+RAG` — плюс индексация шагов и семантический поиск |
| Запустить | Подключает компоненту, собирает инструменты из MCPVA, применяет настройки, запускает прослушивание; в режиме RAG — конфигурирует модель и индексирует шаги |
| Остановить | Останавливает прослушивание, снимает внешний фасад МСП |
| Переиндексировать | (только RAG) Пересоздаёт коллекцию `vanessa_steps` и все коллекции файлов, индексирует всё заново; если RAG включили на работающем сервере — сначала выполнит configure |
| Обновить статус | Опрашивает компоненту (`ПолучитьСтатус`) и, в режиме RAG, прогресс эмбеддинга (`stats`) |
| Скачать компоненту (последний релиз) | Гиперссылка: качает `http1c-addin-full.zip` из последнего релиза GitHub |
| Установить из архива… | Распаковывает скачанный zip в выбранный каталог, проверяет состав бандла и подставляет каталог в «Каталог компоненты» (доступна, пока сервер остановлен) |

Если форма открыта не как плагин, при «Запустить» плагин ищет открытое окно
Vanessa Automation сам; если не нашёл — сообщение «Откройте Vanessa Automation».

## Параметры (автосохраняются в настройках формы)

| Параметр | По умолчанию | Описание |
|---|---|---|
| Порт | 8765 | MCP endpoint: `http://localhost:<порт>/mcp` |
| Каталог компоненты | — | Каталог с `libhttp1cWin.dll` (+ `rcore.dll`, `DirectML.dll` для RAG) |
| Токен авторизации | пусто | Если задан — Bearer-токен (`auth_token`) |
| Вести лог / Файл лога | выкл | Логирование компоненты (`logging_enabled` / `log_path`) |
| Модель | multilingual-e5-small | Имя встроенной модели (список подтягивается из `list_models`) или путь к локальной модели |
| Каталог моделей | пусто | `cache_dir` — куда скачивать модели; пусто = каталог по умолчанию |
| Устройство | auto | `auto` (DirectML с откатом на CPU) / `dml` / `cpu` |
| Коллекции файлов | пусто | Таблица дополнительных коллекций для индексации файлов (см. ниже) |

Статусные поля (не сохраняются): статус сервера, статус индексации, число
зарегистрированных инструментов.

## Коллекции файлов

Таблица «Коллекции файлов» в группе «Семантический поиск (RAG)» позволяет, кроме
шагов VA, проиндексировать произвольные текстовые файлы — например, фича-файлы
проекта. Каждая строка таблицы — отдельная коллекция в `rcore`; индексация
выполняется при запуске в режиме `MCP+RAG` и по кнопке «Переиндексировать»
(после шагов, до опроса статуса).

Колонки:

| Колонка | Назначение |
|---|---|
| Коллекция | Имя коллекции (желательно латиница/цифры/подчёркивание, например `project_features`) — под этим именем коллекция видна MCP-инструментам |
| Описание | Описание коллекции для ИИ-агента — уходит в `collection_description` и попадает в описание инструментов поиска |
| Каталог | Папка с файлами; сканируется рекурсивно (включая подпапки) |
| Расширения | Фильтр расширений: `feature`, `feature;md;txt`, допускается и форма `*.feature`; пусто = `feature` |

Каждый файл индексируется целиком одним вызовом `index_raw` (`doc_id` — полный
путь, `name` — имя файла, `meta.path`/`meta.ext`): ядро само режет текст на
чанки по строкам, поэтому для коллекции работают все поисковые инструменты —
`search` (семантический поиск), `grep` (регулярные выражения) и `get_segment`
(чтение фрагмента файла по строкам, с контекстом до/после). Файлы читаются в
UTF-8; файлы больше 5 МБ пропускаются с сообщением. Строки таблицы без имени
коллекции или каталога пропускаются, перед заливкой коллекция пересоздаётся
(`delete_collection`).

Пример: коллекция `irp_features`, описание «Фича-файлы проекта ИРП (Gherkin,
русские шаги)», каталог `D:\Projects\IRP\features`, расширения `feature` — после
индексации ИИ-агент через MCP ищет по содержимому всех фич проекта семантически
(`search`), по регулярке (`grep`) и читает найденные места из файлов
(`get_segment`).

## Подключение MCP-клиента

```json
{
	"mcpServers": {
		"vanessa": {
			"type": "http",
			"url": "http://localhost:8765/mcp"
		}
	}
}
```

В режиме RAG поиск (`search` / `grep` / `get_segment`) обслуживается самой
компонентой без round-trip в 1С — по коллекции `vanessa_steps` и по всем
коллекциям файлов из таблицы.
