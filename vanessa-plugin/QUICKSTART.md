# MCPRagSearch — быстрый старт

## Зачем это сделано

Штатный MCP Ванессы живёт в расширении `client_mcp`, а поиск шагов там — подстрочный:
«кликаю по кнопке» не найдёт «нажимаю на кнопку», морфология, синонимы и смена языка —
мимо. Плагин **MCPRagSearch** поднимает MCP-сервер целиком на внешней компоненте
**http1c** (C++ транспорт + Rust-ядро поиска) и добавляет **семантический (RAG) поиск**:
ИИ-агент находит шаги по смыслу, задаёт вопросы базе знаний VA и ищет по фича-файлам
проекта. Ядро Ванессы при этом не правится (микро-хук уже в ядре — PR
[Pr-Mex/vanessa-automation#2614](https://github.com/Pr-Mex/vanessa-automation/pull/2614)),
расширение `client_mcp` не требуется.

## Что умеет

- **Все 36 MCP-инструментов VA** (запуск сценариев, анализ форм, шаги, база знаний…) —
  регистрируются из MCPVA автоматически, обслуживаются компонентой.
- **Семантический поиск** (режим `MCP + RAG`), без round-trip в 1С:
  `search` (по смыслу: dense / hybrid / keyword), `grep` (регулярные выражения),
  `get_segment` (чтение фрагмента файла по строкам), `list_collections`
  (какие коллекции проиндексированы).
- **Коллекции из коробки**: `vanessa_steps` (все шаги VA, эмбеддинг обогащён синонимами
  действий) и `vanessa_kb` (база знаний «как правильно писать сценарии», 98 Q&A);
  плюс **свои файловые коллекции** — таблица «Коллекции файлов» (каталог + расширения +
  описание), например фичи проекта.
- **Скил для агента**: MCP-промпт `search-guide` и инструмент-дубль `get_search_guide` —
  готовая инструкция агенту, как и где искать.
- **Автоактуальность**: смена языка генератора Gherkin или библиотек шагов →
  автоматическая переиндексация (проверка раз в 30 секунд).

## Требования

Windows x86-64, платформа 1С 8.3.19+, Vanessa Automation с микро-хуком MCPVA
(ветка `mcp-rag` / PR #2614).

## Запуск

1. **Плагин**: собранный `MCPRagSearch.epf` положить в `plugins/` рядом с
   `vanessa-automation.epf` — или просто открыть как внешнюю обработку в том же сеансе,
   где открыта VA.
2. **Компонента**: на форме плагина нажать гиперссылку **«Скачать компоненту (последний
   релиз)»** (`http1c-addin-full.zip`), затем **«Установить из архива…»** — плагин
   распакует бандл, проверит состав и сам подставит каталог в настройки.
   Если архив скачали и распаковали сами — **«Установить из папки…»**: укажите каталог
   с распакованным бандлом, проверки те же.
3. **Режим работы**:
   - `MCP` — только инструменты VA (быстрый старт, ничего не скачивается);
   - `MCP + RAG` — плюс семантический поиск: выбрать модель (по умолчанию
     `multilingual-e5-small`, рядом ссылка на её страницу), каталог для скачивания
     моделей и устройство (`auto` = GPU/DirectML с откатом на CPU).
     Для работы без сети в поле «Модель» можно указать путь к локальной папке
     модели — состав файлов см. в
     [README.md → «Локальная модель (оффлайн)»](README.md#локальная-модель-оффлайн).
4. Нажать **«Запустить»**. Первый старт в режиме RAG скачает модель и проиндексирует
   шаги — подготовка может занять время, прогресс и счётчики видны на форме.
   Кнопка «Остановить» (или закрытие формы) останавливает сервер.
5. **Подключить MCP-клиента** (Claude Code / VS Code / Cursor…):

   ```json
   {
       "mcpServers": {
           "vanessa": { "type": "http", "url": "http://localhost:8765/mcp" }
       }
   }
   ```

## Подводные камни

- **Лайт-бандл** (без `rcore.dll`): поисковые инструменты отвечают `rag_not_installed` —
  доустановите полный бандл в тот же каталог, компонента подхватит его без перезапуска 1С.
- **Клиент не видит новые инструменты/промпт**: MCP-клиенты кэшируют список при
  подключении — переподключите сервер в клиенте после его запуска/перезапуска.
- **Закрытие формы плагина = остановка сервера** — форму можно свернуть, но не закрывать.
- **Порт занят**: поменяйте «Порт» на форме (по умолчанию 8765) и URL у клиента.

Подробное описание всех настроек, коллекций и протокола — в [README.md](README.md).
